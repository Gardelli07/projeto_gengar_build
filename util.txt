Um ponto de segurança que preciso te contar
O npm audit acusou uma vulnerabilidade moderada real numa dependência transitiva (file-type, usada internamente pelo music-metadata pra detectar o formato do arquivo): um loop infinito ao parsear um arquivo ASF/WMA malformado (GHSA-5v7r-6r5c-r473). Como esse endpoint aceita upload de arquivo do usuário (autenticado, mas ainda assim), mitiguei com um timeout de 5s ao redor da extração — isso evita que um upload malicioso trave a requisição indefinidamente na maioria dos casos, mas não é uma garantia absoluta: se o loop travado for 100% síncrono sem nenhuma chamada assíncrona no meio, um timeout via Promise.race não consegue interromper o thread único do Node no meio da execução (só funciona se o parser ceder o controle em algum ponto, que é o comportamento normal desse tipo de parser baseado em stream).

Como o endpoint exige JWT (não é anônimo), o risco fica restrito a usuários autenticados mal-intencionados — razoável pra fase de teste, mas vale ter no radar antes de ir pra produção. Se quiser, no futuro posso trocar por uma lib bem mais restrita que só entende MP4/M4A (sem o sniffing genérico multi-formato que carrega esse risco), eliminando a superfície de ataque por completo.
